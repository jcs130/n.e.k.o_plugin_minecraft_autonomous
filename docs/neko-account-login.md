# 用猫娘计划账号登录千灯纪

0.6.139 是开发候选，连接页已重排为账号、游戏环境、模型三步。插件的日语显示名已移除。网站官方登录与插件接入链已实现；公网启用还需要千灯纪完成独立 OAuth 应用登记和网站部署，当前公开版本没有因此自动更新。

## 普通用户操作

1. 在 Neko 的插件中心安装插件，打开「配置与控制」，选择千灯纪。
2. 点击「使用猫娘计划账号登录」。新角色昵称默认自动生成；想自行命名时再展开「自定义游戏昵称」。插件只生成并保存一次。
3. 打开面板提供的官网链接，点击「使用猫娘计划账号登录千灯纪」。登录和同意授权在猫娘计划官方页面完成，不在插件输入猫娘计划密码。
4. 核对官网显示的新角色昵称，批准本机这一次申请。插件会继续查询同一申请，成功后私有保存游戏连接与 `/login` 登录材料，无需手输游戏命令、网站密码或邀请码。
5. 准备游戏组件并绑定支持工具调用的模型，点击「开始自主游玩」。不需要先对猫娘说话；停止、保存和重开插件不会自动开始游戏。

网站若尚未启用，面板显示「账号关联暂未开放」，保留原账号和设置，不提交建号。此时可以点击「使用已有账号」，填写原游戏昵称和密码，或导入本人身份文件。已有千灯纪网站账号应先登录原账号，再关联猫娘计划，以保留原角色归属；不会按昵称或邮箱猜测、合并账号。已有游戏身份、手工密码和外部执行器仍使用兼容入口，不被新账号向导接管。

网站会话需要重新验证时，点击「重新验证猫娘计划账号」，必须是已关联的同一个账号。插件查询可暂停并继续；过期且尚未提交建号的申请可显式重新授权，沿用原身份。已提交、未知或失败请求不会通过重试另建角色，也不会自动改密。

## 站点启用条件

站点管理员向猫娘计划登记**千灯纪自己的** OIDC 客户端，使用回调 `https://mc.kangqiang.site/api/v1/auth/neko/callback`、Authorization Code + PKCE S256、`openid` 与 RS256。不能借用 Neko 桌面、市场或社区的 Client ID。官方发现地址为 <https://auth.project-neko.cn/.well-known/openid-configuration>。

门户对应实现和配置在 `minecraft-ai-friend/paper/integrations/agent-portal`，见其 `docs/neko-account-login.md`。登记和配置属于站点管理员的一次性工作，普通用户不需要填写 Client ID、写代码或修改 Neko。只改插件无法替代网站的官方身份认证。

官方已有[网站登录 SDK](https://github.com/Project-N-E-K-O/neko-auth-client)，它不包含给第三方网站分配生产应用的权限。本次没有找到可核实的猫娘计划普通用户自助应用登记入口；若千灯纪维护者没有认证平台的客户端管理权限，需要平台维护者办理登记。登记材料已放在门户 `docs/neko-oauth-application.json`，不是让每个用户申请。

拿到独立应用后，由站点维护者完成容器启用、可信 HTTPS 代理、回调日志脱敏和官网发布，再验证真实登录、本人批准、游戏账号结果与客户端自动登录。原网站账号关联还须核对已有角色和密码保留。源码和离线测试通过，不能代替这些公网步骤。

## 凭据与验收范围

猫娘计划令牌和网站 Cookie 留在网站端。插件只持有自己生成、绑定一个固定新角色请求的私有凭据与游戏密码，保存在当前系统用户的私有账号目录，不随插件或截图发布。游戏自动登录沿用框架的 Windows DPAPI 保存机制；接入身份文件本身不是整个文件的 DPAPI 密文。

离线测试使用隔离的门户与签名身份夹具，覆盖真实 HTTP 路由、一次性状态、签名与账号边界、注销回调、同账号重验及请求恢复。它不证明正式 OAuth 客户端已经登记、公网已部署或新账号已实际入服。本次没有启动游戏、模型、Java、修改 Neko/SDK 或发布市场版本。
