# 缺少后端时的安装恢复

`quick_start` 的 `backend_missing: install the pinned backend first (see README).`
表示选中的后端没有安装到该目录。默认组件尚未准备、旧自定义路径失效，或只保存了
`backend.node` 等自定义项，都可能导致启动未找到固定版本的执行入口；它不证明游戏账号或模型有问题。

0.6.137 开发修复把这类预期安装状态保留为结构化反馈。面板在组件元数据缺失或版本不符时
不再提供可执行的游玩按钮；先显示准备步骤，不以成功受理代替实际游戏启动。

1. 默认安装：点击「准备游戏组件」，等待完整下载、安装和校验。
2. 原自定义目录已经失效：本人明确选择「改用一键游戏组件」，再准备组件。
   此操作只清除后端、渲染器和资源的自定义选择，保留账号、模型、历史及共享数据目录。
   需要保留自定义环境时，应在高级设置修正原路径。
3. 就绪后点击「开始自主游玩」。选择和下载不会替用户自动开始游戏。

外部执行器、Java-client 及远程观战保持原管理边界；活动身体、有效租约、准备中任务、
未结算/未知动作和损坏状态不会被恢复按钮绕过。完整性或源码摘要不符仍拒绝，不能当作
普通缺文件而静默重装。保存结果不明只提示刷新核对，不重复写配置。

复现使用临时数据目录、真实公共 SDK 和固定框架依赖，禁止游戏、模型及网络操作。
旧入口在仅设置 `backend.node="node"` 或缺失自定义目录时产生原样异常；新增回归覆盖
默认组件缺失、路径失效、界面就绪门禁及安全恢复。发布包和现场游玩效果需另行验收；
本说明不表示开发版本已上架。

同时核对发现，先前开发主干已经更新核心，而在线准备清单仍引用 0.6.114 / rc.110
的旧组件。0.6.137 候选改为锁定与框架 0.2.134 / 核心 rc.141 匹配的独立组件包，
包含原固定观战、声音、外观及浏览器资源；不打包 Paper 服务器、身份、模型或存档。
发布时必须同时交付插件与此组件包，不能只更新插件或沿用旧组件的验收结果。
