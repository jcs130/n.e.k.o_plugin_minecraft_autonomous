## 普通使用者安装路径

1. 安装当前支持公共模型槽和插件面板的 N.E.K.O，通过「用户插件／插件中心 → 导入」选择正式生成的 `.neko-plugin`。安装、导入、startup 和状态查询均不自动进入游戏。
2. 安装 Node.js >=22。显式使用与上表匹配的核心归档，按 README 的 `backend/install.py --destination ... --archive ...` 安装到新目录；再运行 `backend/check_disconnected.py --directory ...`。第一次安装需要 npm 注册表网络；离线模式需要预先准备依赖缓存。
3. 在插件配置与控制页填入服务器、端口、账号、认证方式、`version=1.21.1` 和已校验后端的绝对目录。Microsoft 正版认证由正常设备授权流程完成；offline 只用于允许该方式的服务器。不要填写他人的私服或凭据。
4. 默认 embedded 模式在 Neko 公共 `decision` 模型槽配置支持文本及工具调用的模型；也可显式配置支持的直连提供商。可选 vision 未配置时使用文字事实；可选快决策未配置时使用原生规则。没有规划模型时不能宣称已具备完整长期自主规划。
5. 启用自主游玩后手动点击开始。目标用自然语言输入；普通目标排队，新反馈在原生安全检查点插入，明确替换和停止使用对应入口。任务受理与模型宣称完成均不是实际成功。
6. 观战与状态页可独立查看数据统计和回执。完整 3D 观战还需要显式安装共享 renderer 及对应原版资源，或填写已有、与该账号绑定的观战 URL；本候选包不夹带游戏资源和宿主源代码。进入游戏自动打开已配置的同账号观战页。

## 当前功能与限制

- 默认普通 Mineflayer Java 1.21.1，自主运行层和队列独立于 Neko；Neko 提供高层目标、反馈、角色解说和官方语音。
- Minecraft 原版食物、配方等版本化知识按需检索，完整现场原文与查询入口保留；新鲜事实放在请求尾部。
- 结构化拒绝回执附原生技能参考，同一现场的相同拒绝计划暂缓重试；新事实或有界期限后重新检查。没有把烹饪误写成合成时自动偷换为另一动作。
- 技能/魔力/自定义资源等服务器扩展只按实际收到且验证的数据启用，默认不显示千灯纪专用界面。此处不保证任意模组服、Bedrock 或其它协议版本可接入。
- 目前尚未完成完整原版实体/粒子/场景动画一致性与原生截图提供器验收；HTTP 200、图标显示、短时移动和重生满血均不能替代长期生存验收。
- 插件仅使用公共 SDK，未修改 Neko 主程序或 SDK。主脑关闭时独立外部模式仍可持续运行；用户明确停止后不自动恢复。
